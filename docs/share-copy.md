## 一、掘金 / 技术社区版

**标题**：用麦当劳 MCP 做了个减脂配餐 Skill，顺手把菜单穷举了一遍

**正文**：

减脂期想吃麦当劳，最烦的不是热量，是「到底点哪几样」。

所以做了个东西：报上身高体重和每天运动量，它按 Mifflin-St Jeor 算出你的 TDEE 和热量缺口，再从麦当劳 MCP 实时返回的 158 条官方营养数据里，给早/午/晚/加餐各配一套**具体到单品**的组合，最后逐项对照《中国居民膳食指南》。

三个踩坑点值得记一下：

**1. MCP 返回的不是 JSON 数组。** 是一段紧凑表格文本（`[160]{productName,energyKcal,protein,...}` 开头，换行逗号分隔），得自己解析。

**2. MCP 的命名和官网菜单对不上。** 它叫「中薯条 / 小杯玉米杯 / 可乐中杯」，官网菜单是「薯条|中 / 玉米杯|小 / 可口可乐|中」。做了名称归一化 + 份量词消歧 + 相似度兜底三件事，才把 132 个 SKU 全部匹配上——一开始「薯条|小」被错误匹配成了迷你薯条，热量直接少算一半。

**3. 一个反直觉的结论。** 我把「1800–1900 kcal、蛋白质 ≥ 85 g」约束下的所有组合**穷举了一遍**，纯麦当劳一天的脂肪理论下限是 **81 g（39%E）**。也就是说脂肪偏高不是权重没调好，是菜单结构决定的。这个结论在 README 里如实写了，没有粉饰表格。

配餐本身是四餐按 25/35/30/10% 切分，逐餐束搜索 beam=160，代价函数按「热量 > 蛋白质 > 脂肪/钠/糖 > 纤维/钙」排序。

顺带一提：MCP 的 158 条数据和本地快照比对下来只有 2 处字段差异。内置快照本来就是准的，MCP 真正的价值在于**以后菜单变了能第一时间发现**，而不是修历史错误。

仓库：https://github.com/Hank-2333/mcd-fit-planner
